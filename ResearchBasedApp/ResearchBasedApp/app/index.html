백업을 보내고, 전송 결과를 확인합니다

모바일 백업을 다른 기기로 옮기는 사용자가 ZIP을 암호화해 임시 클라우드로 전달하고, 논문에서 사용한 SHA-256 비교 방법으로 전송 전후 파일의 동일성을 확인하도록 돕습니다.

반영한 논문「모바일 애플리케이션 보안 분석 보고서 — Unity 기반 Android 게임의 로컬 데이터 보호 및 기기 간 이식 가능성 분석」
적용 결과: 백업 파일 SHA-256 비교 및 기기 간 데이터 이식 분석
1

백업 ZIP 선택

이동할 파일이나 폴더를 ZIP으로 압축한 뒤 선택합니다.

2

열기 암호 만들기

다른 기기에서 백업을 열 때 필요합니다.

암호를 잊으면 백업을 복구할 수 없습니다.
ZIP의 SHA-256을 계산한 뒤 AES-GCM으로 암호화합니다. 암호와 원본 파일은 서버에 전송되지 않습니다.

전송 코드를 만들었습니다

받는 기기에서 이 코드와 설정한 암호를 입력합니다. 코드는 30분 동안 유효합니다. 만료 후에는 받을 수 없습니다.

전송 전 SHA-256

보내는 기기에서 받은 전송 코드를 입력합니다.
같은 사이트에서 만든 코드와 백업 암호가 필요합니다.
1

전송 코드 입력

전송 코드는 발급 후 30분 동안 유효합니다.

2

백업 암호 입력

보낸 기기에서 설정한 암호를 입력합니다.

전송 코드는 파일을 찾는 번호입니다. ZIP 복호화에는 백업 암호도 필요합니다.

백업을 복호화하고 확인했습니다

전송 전후 ZIP의 SHA-256 값을 비교합니다.

↓ 복호화된 ZIP 저장

↗간단한 3단계

2
암호화·코드 발급전송 전 SHA-256을 기록합니다
3
다른 기기에서 복호화수신 ZIP 해시가 같은지 확인합니다
ⓘ Android 앱 전용 폴더 이동 안내

Android 11 이상에서는 웹페이지가 앱 전용 폴더에 직접 쓸 수 없습니다. 복원에는 해당 기기와 앱이 허용하는 시스템 절차가 필요합니다. MoveKit은 권한 제한을 우회하지 않습니다.

서버에는 암호화된 파일만 임시 저장됩니다. 코드 만료 뒤에는 파일 접근이 차단되며, 저장소 물리 삭제는 후속 만료 정리 작업에서 반영됩니다.
Android 앱 전용 폴더에 직접 저장하거나 권한 제한을 우회하지 않습니다.
브라우저에서 SHA-256 계산 및 AES-GCM 암호화 · 서버에는 암호문만 임시 보관 · 전송 코드는 30분 후 만료
